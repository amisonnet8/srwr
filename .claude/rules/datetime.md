# 日時の扱い

**データでは UTC で持ち、人に見せるときだけ、その人のタイムゾーンに直す。**

## 持つとき（保存・受け渡し）

- ファイル・DB・JSON・ログ・API・設定・テープなど、**人の画面の外に出る日時は、すべて UTC**。形式は RFC 3339 の `Z` つき（`2026-10-14T01:32:00Z`。必要ならミリ秒まで `…:00.123Z`）
- Go では `t.UTC().Format(time.RFC3339)`（ミリ秒は `"2006-01-02T15:04:05.000Z"`）で書く。`time.Local` で書いたものや、`+09:00` などのオフセットつきを**新しく書かない**
- **読むときは、`Z` もオフセットつきも両方読める**ようにする（`time.Parse(time.RFC3339, …)` は両方読む）。古いデータは書き換えない
- ファイル名・ID に日時を入れるなら、それも UTC
- 内部では `time.Time`（瞬間）で扱う。文字列のまま持ち回らない

## 見せるとき（表示）

- 人に見せる境目（画面・CLI の出力・メール・人が読むログ）で、**利用者のタイムゾーンに直す**。Go では `t.Local()`（`TZ` 環境変数・OS の設定に従う）
- タイムゾーン名を固定（`"JST"`・`Asia/Tokyo`）で埋め込まない。利用者の設定に従う。固定が要る仕様（営業日・締め時刻など）は、そのタイムゾーンを**名前（IANA）で設定に持ち**、コードに書かない
- 画面にタイムゾーンの違いが紛れるときは、オフセットや名前を添える

## 比べる・計算する

- 時刻は**瞬間で比べる**（`time.Time.Equal`・`Before`・`After`）。**文字列で比べない**（`Z` と `+09:00` は、同じ瞬間でも文字列が違う）
- 日付だけのもの（誕生日・締め日）は瞬間ではない。タイムゾーンに依存しない**日付として**別に持つ（`2026-10-14`）。UTC の午前0時にして持たない（見る場所で前日・翌日になる）
- 「今」は関数で差し替えられるようにする（`Now func() time.Time`）。**テストは本物の現在時刻に頼らない**

## テスト

- 固定した日時で確かめる。タイムゾーンに関わる変更は、`TZ=UTC` と `TZ=Asia/Tokyo` の両方で流す（手元は JST、CI は UTC のことが多い。文字列比較のテストは、手元でだけ通る）
- 表示が `TZ` に従うことは、`time.Local` を差し替えるテストで確かめる
