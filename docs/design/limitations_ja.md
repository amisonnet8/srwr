# 制限と未定事項

*[English](limitations.md) | **日本語***

**読者**：srwr を使う人、開発に加わる人。設計上の割り切り、決めていないこと、追加の候補。

## 1. 制限（設計上の割り切り）

- **一度も触れないファイルの変更は見えない。** `external` になるのは、テープがすでに内容を持つファイルだけ（基準を持つとテープが大きくなる）。例外は、Bash が作った新しいファイル：git の作業ツリーでは見つけて記録する（`created`）。エージェント自身の Write が作ったファイルは見つけない
- **外部変更が範囲か、範囲より上の行数を変えたあとは、それ以前の範囲トークンが使えない。** 内容の照合で `selection_mismatch` になる。外部変更の中身から、行のずれを推定することはしない
- CR（CRLF）・NUL を含むファイルと、UTF-8 でないファイルは扱えない（`unsupported_file`）
- Edit/Write の禁止と hook は、Claude Code の設定に依存する。他のエージェントでも、`look` / `edit` / `new` / `session` 自体は MCP なので使える
- **VSCode の差分**：行をそろえる空白行がなく、左右のスクロールは連動しない（標準の差分画面を使わないため）
- **VSCode の行番号**：理由の行があるコマでは、実ファイルどおりの番号が、ガターではなく本文の左端に出る
- **理由の折り返し幅**：VSCode は表示の幅100で固定、Vim はウィンドウの幅
- **見せるコマの種類の選択は保存しない。** エディタが動いている間だけ覚え、開き直すと look・edit・external になる。`look` の種類は、AI 自身の `look` と、hook が記録したもの（`why` のないもの）を見分けない
- **failure のコマが範囲を見せるのは `look` のときだけ**（テープには、`file` と行番号で指した `edit` の範囲も残る）。ほかは、ビューワーが `-` を出す
- **ライブは、更新時刻が最新のテープを追う。** ライブを開いている間に `srwr trace --as-tape` が書いたテープが最新になり、ライブがそちらへ移る
- **`srwr trace --as-tape` が切り出したテープには系譜がない**（`selection`・`from` は `null`）。最後の差分は今のファイルとの差なので、コミットのあとの作業が差として出る
- **VSCode は、作業場の最初のフォルダを使う**（ウィンドウごとに表示サーバー1つ）

## 2. 未定

決まっていないこと。決まったら、該当の文書に書き、ここから消す。

- 緩いモードで、エージェント自身の Write が新しいファイルを作ったときの見せ方（今は記録せず、あとでそのファイルに触れたときに見えるだけ）
- 調べる過程のコマが多いときの見せ方。`look` を OFF にすれば全部隠せる（[vscode.md](../reference/vscode_ja.md)）。hook は1回の呼び出しで `look` を100件までしか記録しないので、1回の呼び出しでテープがあふれることはない。`why` のあるものだけを見せるかは決めていない
- 範囲トークンの HMAC の長さ（3バイト。書き写しミスの検出率と文字数のトレードオフ）
- `look` が `lines` を常に返すことの見直し（トークン消費とのトレードオフ。`edit` は `brief` で、すでに省ける）

## 3. 追加の候補

作ると決めたものではない。画面に足すときは、VSCode と Vim の画面の仕様（[vscode.md](../reference/vscode_ja.md)・[vim.md](../reference/vim_ja.md)）を、先に直す。

- **hook の調べる過程のコマだけを飛ばす方法**：hook の記録で `why` なしのコマが多くなったとき、`why` のあるコマだけを追えるようにする（今の種類の選択は、`look` 全体を対象にする）
- **人間の編集のコマ**（`author.kind: human`）：エディタが同じ作業場で動いているので、編集のその場で一言メモを付けられるようにする。付いたメモは `why` の行と同じ形で出す。途中の外部変更に `why` がない問題への答えになりうる
- **途中の外部変更に説明を付ける方法**：`external` の `author` は固定で、誰が変えたか分からない。コミットメッセージや、人が付けるメモの利用が候補（`srwr trace` は、コミットの追加行をどの操作が書いたかを言う。これは別の問い）
- **セッションを区切る時間**（最後のイベントから30分に固定。AI の `session` ツールと `srwr tapes new` は、すぐに区切る）**と、ライブの見張りの間隔**（200ミリ秒に固定）**を、利用者が変えられるようにする**（設定できないものの一覧は [settings.md](../reference/settings_ja.md)）
- **テープの自動整理**（今は、利用者が `srwr tapes prune` で明示的に消す。閉じたテープは、すでに圧縮される）
- **VSCode の拡張に `srwr` のバイナリを同梱する**：テープを受け取っただけの人も、拡張だけで見られる。OS ごとの `.vsix` が要る。今の選択とその理由は [decisions.md](decisions_ja.md)
- 他のエディタへの対応（[protocol.md](../reference/protocol_ja.md) に合わせたクライアントを足す）
- Claude Code 以外のエージェントへの対応
